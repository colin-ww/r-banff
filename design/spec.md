# Spec: `banff` R package (R interface to Banff)

Scope: the 9 Banff procedures, with Python banff behaviour where it matters. Prototype status is marked
✅ done / 🔲 planned.

## User-facing API

```r
library(banff)
banff_install_binaries()                       # once per machine/version (downloads official wheel, no Python)

res <- indata |>
  donorimp(instatus = instat, unit_id = "IDENT", by = "PROV",
           edits = c("Q1 + Q2 + Q3 + Q4 - TOTAL = 0"), post_edits = "Q1 + Q2 + Q3 + Q4 - TOTAL <= 0",
           min_donors = 1, percent_donors = 1, n = 1, seed = 1)
res$outdata        # tibble
res$outstatus
res$log            # full C log, character(1)
```

### Functions ✅

- One function per procedure, same names as Python. Python's aliases are exported too:
  `determin`/`deterministic`, `donorimp`, `editstat`/`editstats`, `errorloc`, `estimato`/`estimator`,
  `massimpu`/`massimp`, `outlier`, `prorate`, `verifyed`/`verifyedits`.
- Generated by `tools/gen_procs.py` from upstream `banff/proc/proc_*.py`. **Never hand-edit
  `R/procs-generated.R`.**
- `banff_run(proc, args, dots)` is the engine behind every wrapper. It's exported for programmatic use.
- `banff_install_binaries(version, index, dest)` and `banff_lib_dir(version)` manage the binaries.

### Argument mapping (Python → R)

| Python | R | Notes |
|---|---|---|
| C params (`unit_id`, `edits`, `seed`, …) | same name, default `NULL` (= let C default) | passed as JSON, no R validation |
| `str` lists (`by="prov naics"`) | `"prov naics"` **or** `c("prov","naics")` | vectors collapsed with spaces |
| `edits="a>0; b>0;"` | string **or** `c("a>0","b>0")` | any param name containing `edits` is collapsed with `; ` and gets a trailing `;` |
| input datasets (`indata`, `instatus`, `indata_hist`, …) | same name; `indata` is always 1st (pipe) | data.frame/tibble, or anything `nanoarrow::as_nanoarrow_array_stream()` takes (arrow Table, …). Factors → character |
| file paths as inputs (`"x.parquet"`, `.sas7bdat`) | ❌ not supported | read the file in R (`arrow`, `haven`, `duckdb`). Keeps the package DRY and dependency-free |
| mandatory outputs (`outdata=…`) | always returned | no file writing. Write in R if needed |
| optional outputs (`outmatching_fields`, `outsummary`, …) | logical, default mirrors Python's `requested_by_default` | `verify_specs`/`verify_edits = TRUE` disables all outputs, as in Python |
| `presort`, `prefill_by_vars` | same, default `TRUE` | mirrored in R ✅ |
| `exclude_where_indata[_hist]` | same, SQL string (duckdb) | needs `duckdb` (Suggests). Idiomatic R alternative: compute a flag column with dplyr + `data_excl_var` |
| `trace`, `capture`, `logger` | ❌ dropped | replaced by `$log` + `options(banff.quiet)` |
| unknown `**kwargs` | error + did-you-mean | C ignores unknown keys silently. `options(banff.pass_unknown = TRUE)` opts out |
| `banff.set_language()` | `options(banff.language = "fr")` | loads the `_fr` build. Default: from `LC_MESSAGES` |
| `get/set_default_output_spec` | ❌ n/a | always tibbles |

### Return value ✅

- A `banff_result`: a named list with one tibble per *requested* output, plus `log` (character, the C log).
- It has a `print` method that shows dims per output.
- Column names and types are as produced by C: `double` for numerics (C writes doubles), `character` for strings.

### Errors ✅

- A non-zero C return code becomes an R condition of class `c("banff_error", "error", "condition")`
  with fields `rc`, `log` and a message built from the C `get_rc_description()`.
- Catch it with `tryCatch(..., banff_error = function(e) e$log)`.
- Unknown parameter names raise a plain R error before any C call.

### Logging ✅

- C `stdout` is redirected to a temp file during the call (`dup2`), returned as `$log` and echoed with
  `message()`. That means it's suppressible with `suppressMessages()` or `options(banff.quiet = TRUE)`.
- 🔲 Later options: `banff.log_file` (append the log to a file); keep progress streaming for long runs.

### Options

| Option | Default | Meaning |
|---|---|---|
| `banff.backend` | `"c"` | `"python"` = go through reticulate (oracle/fallback) |
| `banff.quiet` | `FALSE` | don't echo the C log |
| `banff.language` | from locale | `"en"` / `"fr"` |
| `banff.lib_dir` / env `BANFF_LIB_DIR` | `R_user_dir("banff","data")/<ver>/<platform>` | where the `.so`/`.dll` live (can point at a pip install) |
| `banff.pypi_index` | `https://pypi.org/simple` | simple index for `banff_install_binaries()`, e.g. an Artifactory PyPI remote |
| `banff.pass_unknown` | `FALSE` | pass unknown param names to C |

## Internals

```
donorimp(...)                                   R/procs-generated.R   (generated)
 └ banff_run()                                  R/run.R
    ├ check_unknown()            names only
    ├ requested_outputs()        from .banff_specs (generated)
    ├ collapse_parms()           vectors → strings
    ├ preprocess()               exclude_where (duckdb) → prefill_by_vars → presort   (mirror of Python)
    ├ jsonlite::toJSON()         params
    ├ nanoarrow streams          inputs; allocate schema/array per requested output
    ├ .Call(rbanff_call, …)      src/shim.c: dispatch on arg count, dup2 stdout → temp file
    └ nanoarrow → tibble         outputs
```

- **ABI table** `.banff_specs[[proc]]` (generated) holds `inputs` and `outputs` (C argument order), `optional_default`,
  `c_parms`, `verify_param`.
- **Libraries** are `dyn.load(local = TRUE)` once per proc × language, then cached. Symbols used: `<proc>`,
  `flush_std_buffers`, `get_rc_description`.
- **Memory / ownership**: inputs go in as `ArrowArrayStream`s, which the C code consumes. Outputs are
  `ArrowSchema` + `ArrowArray` that C fills; nanoarrow owns them and releases them on GC.
- **Thread/locale**: R already runs with `LC_NUMERIC = "C"`, which is what Python sets around the call.

## Platforms

- ✅ Linux x86_64 (The Zone / RStudio Server, k8s jobs).
- 🔲 Windows x64. Code paths exist (`_dup2`, `.dll` naming), untested. Needs Rtools or a prebuilt binary R package.
- ❌ macOS / arm64: upstream ships no binaries. That would need the source build (plan phase 3).

## Non-goals

- Reading or writing files (SAS, parquet, csv). R already does this well.
- The Banff Processor (metadata-driven flows). Possible later as a separate package.
- Re-validating methodology. Results are by construction the C library's results.
